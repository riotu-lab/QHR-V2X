# Comparison charts — nominal-parameter configuration

Generated by [`experiments/scripts/generate_comparison_charts.py`](../../scripts/generate_comparison_charts.py):

```bash
python experiments/scripts/generate_comparison_charts.py --seeds 20 --repeats 3
```

These charts run the three algorithms at the obstacle densities Table 1 states,
averaged over 20 independent seeds, with every metric measured through one shared
search skeleton so RDM, RDT, PL and Ne each have a single definition.

## Configuration

| | |
| --- | --- |
| Obstacle density | 40% (dense) / 20% (sparse), exactly, at every grid size |
| Seeds | 20 per grid size, averaged |
| Endpoints | drawn from the largest connected free component |
| Message counting | one counter for all three algorithms |
| Implementations | self-contained, in the script itself |

Endpoints are not corner-to-corner because at 40% density they cannot be: the
free-cell fraction of 0.60 sits just above the 2-D site-percolation threshold
p_c ≈ 0.5927, so opposite corners of a large grid are almost never connected — a
75×75 draw failed 200 consecutive solvability checks. `Supp_solvability_vs_density.png`
documents this. Endpoints are instead an approximate-diameter pair inside the
largest component, which keeps every instance solvable without lowering the density.

## Regenerating

Re-running the command above reproduces 15 of the 17 charts byte-identically, and
every deterministic column of the CSVs. Three files legitimately change:

| File | Why |
| --- | --- |
| `Supp_measured_time_dense.png`, `Supp_measured_time_sparse.png` | plot measured wall-clock time |
| `../comparison_*.csv` (`wall_ms` column only) | measured wall-clock time |
| `../comparison_summary.md` | quotes those timings |

Wall-clock is machine-dependent, so it differs between any two computers. Message
counts, expansions and path lengths are seeded and identical everywhere. If those
change, something is genuinely wrong; a `wall_ms` diff is expected.

Underlying measurements: [`../comparison_dense.csv`](../comparison_dense.csv),
[`../comparison_sparse.csv`](../comparison_sparse.csv),
[`../comparison_summary.md`](../comparison_summary.md).

## Relationship to `paper_figures/`

[`../paper_figures/`](../paper_figures/) contains the same six Section IV figures
under a **different configuration** — the one the `tests/` harness builds, which
reproduces the published values. The two disagree, and the disagreement is the
point:

| Dense RDM @ 100×100 | `paper_figures/` | here |
| --- | --- | --- |
| Dijkstra | 8919.3 | 7081.9 |
| A* | 4771.3 | 5831.9 |
| QHR-V2X | 194.2 | 5826.4 |

The `tests/` harness places `int(size × density)` obstacles rather than
`int(size² × density)`, so its realised density falls as the grid grows — 1.56% at
100×100 against a nominal 40%. Its figures match the published numbers; these match
the published parameters.
